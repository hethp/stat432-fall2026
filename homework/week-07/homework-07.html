b. Does the method work?

Yes, QDA works here. With 256 pixels, several per-class covariance matrices are singular (rank < 256) because many pixels have zero or near-zero variance within a digit class. By selecting only the 40 highest-variance pixels, we eliminate the near-constant columns, so every 10-class within-group covariance matrix is full rank (40 < n_k for all classes). The misclassification rate is reasonable, confirming QDA is fitting and predicting successfully.

With only 10 predictors the test error is higher than with 40 predictors. Ten pixels capture far less of the spatial variation among digits: many digit pairs (e.g. 3 vs 5, 4 vs 9) differ in pixel regions not captured by the 10 highest-variance columns, so QDA cannot distinguish them. While 10 predictors ensure larger effective sample sizes relative to dimensionality (reducing variance), the severe loss of discriminative information (increased bias) dominates, raising the overall error.

c. Discussion

Small ρ (0 to ~0.2): The two classes share the same covariance structure (ρ = 0 gives identical covariance matrices). LDA's equal-covariance assumption is correct, so it is efficient and has low variance. QDA estimates separate covariance matrices per class, introducing extra variance from the additional parameters without any bias reduction. Thus LDA ≤ QDA in test error.

Large ρ (0.6 to 0.9): The covariance matrices differ substantially between classes (one has positive off-diagonal ρ, the other has −ρ). LDA's pooled covariance is now biased — it averages two genuinely different structures. QDA correctly models each class's covariance, so the bias reduction outweighs the extra variance, and QDA achieves lower test error than LDA.

Role of the eight noise covariates: These covariates carry no information about the class label, yet both methods must estimate their covariance entries. For QDA this means estimating two full 10×10 covariance matrices (110 free parameters) instead of just the 2×2 informative block. With only 100 training observations per class, the extra noise dimensions increase estimation variance, degrading QDA more than LDA (which pools into one matrix). This is a concrete instance of the bias–variance trade‑off: noise dimensions penalize the more flexible model (QDA) disproportionately.

Findings and Limitations

Ordinary LDA and QDA perform comparably on SAheart. The small sample size (n = 462) and moderate class imbalance limit the power of more flexible models like QDA, which must estimate a full covariance matrix per class. # LDA / QDA Classification Analysis Skill

## Purpose
Perform a systematic binary or multi-class classification study using
Linear Discriminant Analysis (LDA), Quadratic Discriminant Analysis (QDA),
and optional extensions (PCA pre-processing, LDA–QDA probability blending).
Produce a **one-page analysis report** with a figure, a table, and
numerical fitting results.

## Inputs (supplied at invocation)
| Input       | Description                                         |
|-------------|-----------------------------------------------------|
| `dataset`   | Path or DataFrame with the analysis data            |
| `response`  | Name or index of the response (class label) column  |
| `predictors`| Names or indices of predictor columns               |
| `seed`      | Random seed for reproducibility                     |

## Analysis Workflow

### 1. Data Preparation
- Load and inspect the dataset; report n, p, and class distribution.
- Encode categorical predictors numerically if needed.
- Reserve **25 %** of data as a **held-out test set** via stratified
  random split.  All model selection uses only the remaining training data.

### 2. Candidate Models
Fit the following classifiers on the training data.  Always include
(a) and (b); the rest are optional.

| ID  | Model                        | Details                            |
|-----|------------------------------|------------------------------------|
| (a) | Ordinary LDA                 | `solver='svd'`, empirical priors   |
| (b) | Ordinary QDA                 | `tol=1e-8`, empirical priors       |
| (c) | PCA + LDA                    | Standardise → PCA(k) → LDA; tune k|
| (d) | PCA + QDA                    | Standardise → PCA(k) → QDA; tune k|
| (e) | LDA–QDA blend                | α·P_LDA + (1−α)·P_QDA; tune α     |

For PCA models, search k ∈ {2, 3, …, min(p, 15)}.
For blending, search α ∈ {0.0, 0.1, …, 1.0}.
Estimate PCA/StandardScaler within each CV fold (fit on fold-train only).

### 3. Cross-Validation
- Use **5-fold stratified CV** on the training data.
- Use the **same folds** for all candidates.
- Metric: **misclassification rate** (1 − accuracy).
- Report mean CV error ± standard deviation for every candidate.

### 4. Model Selection and Final Evaluation
- Select the candidate with the **lowest mean CV misclassification rate**.
  Break ties by preferring the simpler model (LDA > QDA > PCA+LDA > …).
- Refit the selected model (including any preprocessing) on **all**
  training observations.
- Predict the held-out test set **once**.  Report the test
  misclassification rate and test confusion matrix.

### 5. One-Page Report Format
The report must fit on **one printed page** and contain exactly:

1. **Title and seed** — analysis title, random seed used.
2. **Data summary** — one sentence: n, p, class balance.
3. **Figure** — a single plot showing CV error bars for each candidate
   model (bar chart or dot plot with error bars for ± 1 SD).
4. **Table** — rows = candidate models, columns = mean CV error, SD,
   and whether the model was selected.
5. **Selected model** — state which model was chosen and why.
6. **Test result** — test misclassification rate and confusion matrix.
7. **Findings and limitations** — 2–3 sentences on performance,
   and a note on limitations (e.g., small n, class imbalance).

### Style Guidelines
- Use a clean sans-serif font; colour-blind-safe palette.
- Figure: 6 × 3.5 inches, minimal grid, labelled axes.
- Table: compact, no excessive whitespace.
- Keep prose minimal — prefer numbers and visuals.

### Output
Return the one-page report as an HTML fragment (headings, figure as
embedded base64 PNG, and an HTML table) that can be inserted directly
into a homework document.
